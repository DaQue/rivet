## Hazards — real bug classes, one of which already shipped in this project

**H1 — Number bases. Do not fold ASCII digits in the wrong base.** A sibling module shipped
`acc * 10 + digit` to parse a *hexadecimal/octal* field; it compiled, and its damage only showed as
a wrong value at runtime. Here there are two numeric fields and both need care:
- `when` is **decimal**, may be **negative** (pre-1970 commits are legal — do not reject them), and
  must not be clamped or defaulted.
- the offset is `±hhmm`: a sign, two decimal **hours**, two decimal **minutes** — `minutes = sign *
  (hh * 60 + mm)`. Parsing `hhmm` as a single number is wrong (`+0530` is not 530).
- `-0000` is Git's "offset unknown" and equals `+0000` once reduced to minutes, so a *field-level*
  round-trip of `-0000` is **not** required. Byte round-trip goes through the raw body
  (`Commit::raw` / `to_bytes`), which is exactly why that field exists.

**H2 — `Signature::parse` splits from the RIGHT.** Git takes the **last** `>` on the line, because a
display name may legally contain `<` and `>`. A left-to-right parse mis-splits real commits. Verify
with a name like `A <B> C <a@b.example> 100 +0000`. A missing email, a missing timestamp or a
malformed offset is an **error**, never a zero-filled default: defaulting invents an author and
changes the commit's id.

**H3 — Unmodelled headers survive verbatim, and `header()` unfolds.** `extra_headers` keeps each
header's raw value with its folding; `header(name)` returns the **unfolded** value (continuation
lines joined, leading spaces dropped, no trailing newline) — `verify-commit` needs `gpgsig` whole.
Name matching is byte-exact and case-sensitive. A commit carrying a multi-line `gpgsig` must satisfy
`parse(format, input).unwrap().to_bytes() == input`.

**H4 — Message rules.** `summary` is the first **paragraph** folded to one line (Git joins the
wrapped subject with spaces — taking only the first `\n` is visibly wrong), `body` is everything
after the first blank line and is **empty** when there is no blank line (not equal to the subject),
`is_merge` is `parents.len() >= 2` (octopus merges are legal, so do not assume exactly two).
`build` accepts an **empty message**; the `-m ""` refusal is a CLI policy, not this function's.

**H5 — Reuse the crate's hasher.** `Commit::id` must go through the existing object-hashing helper
in `object/mod.rs` (the same one that prepends `<kind> <len>\0`); do not hand-roll that header.

yourself with `git hash-object -t commit --stdin`. An invented fixture, or one whose hash you never
verified, is a test that can pass while the code is wrong.

either the implementation is wrong (fix it) or your expectation was wrong (fix the expectation) —

doc comment, STOP and report it rather than bending the test to match the output.
