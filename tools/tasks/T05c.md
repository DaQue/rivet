## Target functions (find by name)

| line | function | required behaviour |
|------|----------|--------------------|
| 913 | `Index::entry` | binary search the sorted entries for `path` + **stage 0**; `None` when only conflict stages exist. Compare with `compare_entries` semantics. |
| 931 | `Index::entry_at` | exact `(path, stage)` → `Ok(Some)`/`Ok(None)`. Do not invent an unsorted-order error; `Ok(None)` for absent. |
| 945 | `Index::insert` | replace the entry with the same path **and stage**, return the displaced one; otherwise push and return `None`. Does not sort. |
| 956 | `Index::remove` | remove by path **and stage**, return it. Other stages of the same path stay. |
| 968 | `Index::sort` | `sort_by(compare_entries)`, and it must be **stable** (use `sort_by` / `sort_by_key`, not `sort_unstable`). |
| 979 | `Index::has_conflicts` | any entry with stage != `Normal`. |
| 990 | `Index::is_sorted` | every window of two is `compare_entries(a, b) != Greater`. |
| 1015 | `Index::is_racy` | `(entry.mtime_seconds, entry.mtime_nanos) >= index_mtime` (tuple compare, nanoseconds included). |
| 1022 | `Default for Index` | `Index::new()`. |

Then **add** `impl IndexExt for Index` after the trait definition (the trait exists, the impl does
not). Implement:

* `stages(path)` — every entry for the path, in file order (so stages ascending on a sorted index).
* `is_unmerged(path)` — has entries and none is stage 0.
* `conflicts()` — distinct paths that have a non-zero stage, **sorted by path bytes**.
* `remove_path(path)` — remove every stage for the path, return them in file order.
* `resolve(path, entry)` — if `entry.path != path` return
  `Error::CorruptIndex { offset: 0, reason: "resolved entry path does not match the target" }`;
  otherwise remove every stage for the path and insert the one entry (stage from `entry.flags`).
* `paths()` — one `&BStr` per entry, file order (conflicted paths repeat).
* `under(prefix)` — component-wise prefix: empty prefix → all entries; else `p == prefix` or
  `p` starts with `prefix` followed by `/`. **`src` must not match `srcfile.c`.**
* `write_tree(odb)` — leave `todo!()`; T05d owns it. The trait impl must still compile.

## Tests

### In `index/mod.rs` (`#[cfg(test)]`, extend the module T05a created)

1. `lookup_finds_stage_zero_only` — parse the git-written capture from T05a or build entries;
   `entry(b"a.txt")` finds it; a path with only stage 2 returns `None`; `entry_at` finds the stage.
2. `insert_and_remove_are_per_stage` — insert stages 1, 2, 3 for one path (distinct oids); replacing
   stage 2 keeps 1 and 3; removing stage 0 does not remove them; `sort` keeps all three adjacent and
   ordered 1 < 2 < 3.
3. `sort_is_stable_and_matches_compare_entries` — shuffle a list including duplicate keys, sort,
   assert `is_sorted()`, and that equal keys keep their input order.
4. `conflict_helpers_agree` — `has_conflicts`, `is_unmerged`, `conflicts()` (one entry per path),
   `resolve()` leaves exactly one stage-0 entry, `remove_path` clears the path.
5. `is_racy_compares_nanoseconds` — mtime 1 ns below index mtime → false; equal → true; nanos
   greater → true; seconds greater → true.
6. `under_matches_components_not_bytes` — entries `src/a`, `src/b/c`, `srcfile.c`, `other`: `under(b"src")`
   is the first two; `under(b"")` is all; exact `under(b"srcfile.c")` is that one.
7. `default_is_an_empty_v2_index`.

### In `tests/index_git_differential.rs` (append)

8. `sort_order_matches_git` — repo with paths `a.b`, `a/b`, `a/b/c`, `a0`, `x/y`, `x-y`; `git add -A`;
   parse the index; shuffle a clone, `sort()` it, and assert the order equals the order in the
   git-written file (git wrote it sorted). This catches the `.`/`/` byte rule.
9. `conflict_index_from_git_merge` — create a real modify/modify conflict (`git init`, commit
   `f` on `main`, branch, change `f` on both sides, `git merge` expecting failure), then parse
   `.git/index` and assert `has_conflicts()`, `conflicts() == [b"f"]`, stages 1/2/3 exist with
   three distinct oids, `entry(b"f")` is `None`, and `is_sorted()`. `resolve` it with the stage-2
   entry and assert the conflict is gone. Do not require the merge command to exit 0.
