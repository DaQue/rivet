# T05d — `IndexExt::write_tree`: build Git trees from the index (4 of 4)

## Goal

## What `write_tree` must do

`fn write_tree(&self, odb: &crate::odb::Odb) -> Result<ObjectId>`

1. **Refuse conflicts first.** If any entry has a non-zero stage, return
   `Error::UnmergedPath { path }` for the first such path in index order. Do not pick a stage.
2. Group the flat `path` list into a hierarchy on `/`. A **tree** is built per directory:
   * a leaf entry becomes `TreeEntry { mode: entry.mode, name: last component, oid: entry.oid }`;
     `Commit` (gitlink) and `Link` (symlink) entries are **leaves**, never descended;
   * a component that has further components becomes a subdirectory: recurse, then
     `odb.write(&Object::Tree(sub_bytes))` and use its returned id as a `TreeEntry` with
     `mode: EntryMode::Tree`.
3. **Sort each tree with Git's rule, which is not `compare_entries`.** Compare names as bytes with a
   `/` appended to directory names — i.e. key = `name` for blobs, `name + b"/"` for trees, plain
   `memcmp` on those keys. (Verified against git: this makes `a.b` < `a/b`, `a0` > `a/`.)
4. Serialise a tree with `Tree { data: &[], entries }` → `.serialize()` → bytes. The id is
   **`hash_object(format, ObjectKind::Tree, &bytes)`** (or re-wrap `Tree { data: &bytes, .. }` and
   call `.id(format)`; note `Tree::id` hashes `data`, so set it to the serialised bytes). Write the
   bytes with `odb.write(&Object::Tree(bytes))` and use the id it returns.
5. **Empty index → the empty tree id**, not an error. Git's SHA-1 value is
   `4b825dc642cb6eb9a060e54bf8d69288fbee4904` (write it to the odb too).
6. A path that is both a file and a directory prefix (`a` and `a/b`) is corrupt index data: return
   `Error::CorruptIndex { offset: 0, reason: "index has a file/directory conflict" }`, not a panic.
7. The format is `odb.format()` (check the accessor's name; it exists). Path components are bytes;
   do not convert to `String`.

Suggested shape: a private recursive helper taking the entries of one directory plus the byte
offset where the child component starts. The index's memcmp order guarantees entries under one
directory are contiguous, but grouping with a small `Vec` and sorting the names is simpler and
correct; do not add dependencies.

## Tests (append to `tests/index_git_differential.rs`)

1. `write_tree_matches_git_tree_ids` — repo with `a`, `dir/nested.txt`, `dir/sub/deep.txt`,
   `run.sh` (0755), `link` (symlink), a 6-character name, and an `empty` directory; `git add -A`.
   For the same repo: `git write-tree` vs `Index::load(...).write_tree(&odb)`. Assert equal ids and
   that `git cat-file -p <id>` is available (the tree was written, not just hashed). Then run
   `git fsck --strict` and fail only on `error`/`missing`/`corrupt`/`fatal` lines; `dangling` is OK.
2. `empty_index_gives_the_empty_tree` — `Index::new().write_tree(&odb)` equals the known empty id
   above (compute it from `git hash-object -t tree /dev/null` instead of hard-coding if preferred).
3. `gitlink_is_a_leaf` — make one commit, then
   `git update-index --add --cacheinfo 160000,<HEAD id>,sub`; `git write-tree` vs rivet's
   `write_tree` must agree. This proves a `160000` entry is not descended into and its id is not
   looked up in this repository's odb.
4. `conflict_is_refused` — feed an index with stages 1/2 for one path → `UnmergedPath { path }`,
   and no tree object was written for it.
5. `file_directory_conflict_is_reported` — hand-build stage-0 entries `a` and `a/b` → `CorruptIndex`,
   no panic.

Open the odb with `Odb::open(<git dir>, ObjectFormat::Sha1)` and load the index with
`Index::load`. Skip with a message if `git --version` fails.
