### 2b. L604, L610, L616, L619 — E0624, `.as_bytes()` is private

Inside `build()`: `object.to_hex().as_bytes()`, `self.name.as_bytes()`,
`self.message.as_bytes()`, `sig.as_bytes()`.

- L610 → `out.extend_from_slice(&self.name[..]);`
- L616 → `out.extend_from_slice(&self.message[..]);`
- L619 → `out.extend_from_slice(&sig[..]);`

Do **not** add `use bstr::ByteSlice;` — it does not fix the `BString` cases.

## Step 3 — the as_bytes rule, applied to the whole file

**Never call `.as_bytes()` anywhere in `tag.rs` again.** Three cases:

| Value type | Examples | Fix |
|---|---|---|
| `BString` | `obj.to_hex()`, `tagger.name`, `tagger.email` | `&x[..]` |
| `&BStr` | `tag.name()`, `tag.signature().unwrap()` | `&x[..]` — or drop the call, since `&BStr` derefs to `[u8]` (`.starts_with(b"…")` works directly) |
| `&[u8]` | `tag.message()` | **drop the call entirely** — it is already bytes |

That single rule clears **21 × E0624** and **5 × E0599**, in both the implementation
and the tests (test lines 653, 677, 678, 679, 682, 694, 708, 711, 724, 736, 762, 774,

## Pinned semantics — do NOT "fix" these to match anything else

1. No `tagger` header → `Error::MissingHeader { kind: ObjectKind::Tag, header: "tagger" }`.
   (`Tag::tagger` is not an `Option`; this is a deliberate, documented deviation.)
2. `build()` with no kind → `Error::MissingHeader { header: "type" }`.
3. Object ids in headers are parsed with `ObjectId::from_hex`, never `from_bytes`.
4. Signature scan covers **all four** armour headers, and the marker must be at
   index 0 or immediately after a `\n` of the message region.
5. The message keeps the newline that precedes the armour; the signature runs to the
   end of the body and includes both armour lines verbatim.

If a *runtime* test failure contradicts one of these, **stop and report** instead of
changing the semantics.
