## Measured ground truth (real git on this machine)

From `git hash-object -t commit --literally --stdin` + `git log --format=%an/%ae/%at`,
on author lines of the form `author <LINE> 1000 +0000`:

* `A <a@b.example>` → name `A`, email `a@b.example` (fsck: clean)
* `A  <a@b.example>` (2 spaces) → name `A` (clean)
* `A   <a@b.example>` (3 spaces) → name `A` (clean)
* `A    <a@b.example>` (4 spaces) → name `A` (clean)
* `A<a@b.example>` → name `A`, email `a@b.example` (fsck: `missingSpaceBeforeEmail`)
* ` <a@b.example>` (empty name) → name ``, email `a@b.example` (clean)
* `A B <a@b.example>` → name `A B` (clean — inner spaces kept)
* `A > B <a@b.example>` → name `A > B`, email `a@b.example` (fsck: `badName`)
* `A <B> C <a@b.example>` → name `A`, email `B`, when `1000` (fsck: `badDate`)

Three rules follow, and they are what the implementation must match:

1. the email runs from the **first** `<` to the **first** `>` after it (not the last `<`/`>`);
2. the name is everything before that first `<`, with **all** trailing spaces removed
   (inner spaces preserved);
3. seconds + offset are read from the **right end of the whole line**, not from the
   text immediately after `>`. In the last case above three tokens follow the first `>`
   and git still reports `when=1000`.

## FIX 2 — `Signature::parse` must split like real git (1 failure)

Current code (~lines 104–143) finds the **last** `>` and then the **last** `<` before it,
never trims the name, and then requires everything after `>` to be exactly two tokens.
Replace that block with the measured algorithm:

```rust
        let open = line.iter().position(|b| *b == b'<').ok_or_else(|| {
            Error::MalformedObject {
                kind: ObjectKind::Commit,
                reason: "no '<' found before the '>' in signature".to_string(),
            }
        })?;
        let close = line[open + 1..]
            .iter()
            .position(|b| *b == b'>')
            .map(|i| open + 1 + i)
            .ok_or_else(|| Error::MalformedObject {
                kind: ObjectKind::Commit,
                reason: "no '<' found before the '>' in signature".to_string(),
            })?;
        // git trims every trailing space before the '<'; inner spaces are kept.
        let mut name_bytes: &[u8] = &line[..open];
        while let Some((&b' ', rest)) = name_bytes.split_last() {
            name_bytes = rest;
        }
        let name = BString::from(name_bytes);
        let email = BString::from(&line[open + 1..close]);
        if email.is_empty() {
            return Err(Error::MalformedObject {
                kind: ObjectKind::Commit,
                reason: "empty email address in signature".to_string(),
            });
        }
        // git reads the timestamp from the RIGHT end of the line, so anything left
        // over between the closing '>' and the last two tokens is ignored.
        let toks: Vec<&[u8]> = line.fields().collect();
        if toks.len() < 2 {
            return Err(Error::MalformedObject {
                kind: ObjectKind::Commit,
                reason: "signature must be `name <email> <seconds> <±hhmm>`".to_string(),
            });
        }
        let when = parse_decimal(BStr::new(toks[toks.len() - 2])).ok_or_else(|| {
            Error::MalformedObject {
                kind: ObjectKind::Commit,
                reason: "signature timestamp is not a decimal integer".to_string(),
            }
        })?;
        let tz_offset_minutes =
            parse_tz_offset(BStr::new(toks[toks.len() - 1])).ok_or_else(|| {
                Error::MalformedObject {
                    kind: ObjectKind::Commit,
                    reason: "signature timezone offset is not ±hhmm".to_string(),
                }
            })?;
```

Adapt the exact argument types of `parse_decimal` / `parse_tz_offset` to the signatures
you already implemented — the error messages and the returned `Self { .. }` stay as they
are. If `BStr::new` needs a `&[u8]` borrow, pass it in whatever form compiles; the rule is
the *behaviour* above, not the literal borrowing syntax.
