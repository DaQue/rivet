# T06c — `packed-refs`: parse, serialise, atomic write, set operations

## Goal

Implement every `todo!()` in `crates/rivet-core/src/refs/packed.rs` (about 26 bodies, all small
except `parse`). Real git's `packed-refs` is the oracle: a file rivet writes must be one git reads,
and rivet must read what `git pack-refs` writes byte-for-byte.

## Read discipline

* **At most 8 `Read` calls**, each with `offset` + `limit`, no window over 150 lines.
* **First `Edit` by tool call #8.** No Bash file reading; Bash for `cargo`/`git` only.

## Files you may edit (only these two)

* `crates/rivet-core/src/refs/packed.rs`
* `crates/rivet-core/tests/refs_git_differential.rs` (append if it exists; otherwise create it)

`RefLock` and `RefName` are already implemented — call them, do not edit those files. Frozen:
signatures, types, visibility, doc comments. No new dependency.

## Format (verified against git 2.56)

```
# pack-refs with: peeled fully-peeled sorted <-- header, optional, note the trailing space
<full-width lowercase hex> refs/heads/main
<full-width lowercase hex> refs/tags/v1.0
^<full-width lowercase hex>                      <-- only after a ref, peels it
```

* A missing file is an empty set; an empty file is an empty set.
* Header: a line starting with `HEADER_PREFIX` (`# pack-refs with:`); the traits are the
  space-separated words after it, ignoring the trailing empty token. Other `#` lines are comments.
* Ref line: split on the **first space only**; the id must be exactly `format.hex_len()` hex digits
  and the rest is the name, verbatim to end of line (so a space in the name is *not* truncation —
  the name will then fail `RefName::parse`, which is the correct result).
* Peel line `^<id>`: attaches to the previous ref; before any ref → `CorruptPackedRefs { line,
  reason }`.
* Blank lines are skipped; one trailing `\r` is stripped from every line (CRLF files).
* A duplicate name later in the file **wins** (replace the earlier entry in place).
* Bad id/length → `CorruptPackedRefs { line, reason }` (1-based). Invalid name →
  `InvalidRefName` as returned by `RefName::parse`.

## Tests

### In `packed.rs` (`#[cfg(test)]`; none exists)

1. `parse_and_serialize_golden` — the exact three-line file above (with header and trailing space,
   one ref and one peel) round-trips byte-for-byte; traits are `[peeled, fully-peeled, sorted]`.
2. `headerless_file_round_trips_without_a_header` — two ref lines, no header; `serialize` has none.
3. `crlf_and_first_space_split` — `\r\n` lines parse; a name with a space reaches
   `RefName::parse` (and therefore errors) instead of being truncated at the space.
4. `peel_before_ref_is_corruption`, `bad_hex_is_corruption`, `invalid_name_is_reported` — with the
   right 1-based line numbers.
5. `duplicate_last_wins`, `insert_replaces_in_place`, `remove_and_retain`, `set_peeled_missing_is_noop`.
6. `sort_is_byte_order` — `refs/heads/a.b` before `refs/heads/a/b`, `refs/tags/v10` before
   `refs/tags/v2` (byte order).
7. `iterator_yields_names_and_size_hint`; `default_is_empty`; `location_covers_three_cases`.

### `tests/refs_git_differential.rs` (append/create; real git is the oracle)

8. `git_packed_refs_round_trips` — `git init`; two commits; `git branch feature/x`; `git tag -a v1
   -m t`; `git pack-refs --all --prune`; read `packed-refs`; `PackedRefs::parse` then `serialize`
   equals the file **byte for byte**; `get`/`peeled` agree with `git show-ref -d`.
9. `rivet_written_packed_refs_git_reads` — parse the git file, `insert` a new branch entry, `sort`,
   `write` to a temp copy path via a temp git dir (`RefLock` uses the path you pass), then run
   `git show-ref` with `GIT_DIR` pointing at that directory and assert it lists the added ref. (If
   simpler: write through `PackedRefs::write` in the temp repo, then `git show-ref`.)
10. `sha256_packed_refs` — `git init --object-format=sha256`, commit, tag, `git pack-refs --all`,
    parse with `Sha256`, round-trip byte-identical.
11. `write_respects_the_lock` — create `packed-refs.lock`, `write` returns `LockHeld`, then removing
    it makes the write succeed and leave no lock.

Skip with a message if `git --version` fails. Tests must fail if the trailing space, the peel
attachment or the last-wins rule is removed.
