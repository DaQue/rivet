## Git-verified layout — use these numbers, not the frozen doc comments

Real git 2.56 was run over the fixtures below. **Every multi-byte integer is big-endian.**
`ObjectFormat::len()` bytes of object id (20 for SHA-1, 32 for SHA-256).

An entry is, from its own start:

```
u32 ctime_seconds, u32 ctime_nanos, u32 mtime_seconds, u32 mtime_nanos,
u32 dev, u32 ino, u32 mode, u32 uid, u32 gid, u32 size,
id (format.len() bytes),
u16 flags, [u16 extended_flags only if flags bit 14 is set],
path bytes, NUL, zero padding so the entry's total length is a multiple of 8
```

First flags word: bit 15 assume-valid, **bit 14 extended**, bits 13–12 stage, bits 11–0 path
length. Second word: **bit 14 skip-worktree**, **bit 13 intent-to-add**, bits 12–0 extended mode
bits. (`0x4000` and `0x2000` were read out of a real v3 index written by
`git update-index --skip-worktree` / `git add -N`.)

### CRITICAL: the 12-bit name length EXCLUDES the NUL

The frozen doc comments at lines 247–249, 261–265, 317–323, 330–334, 495 and the `NAME_LENGTH_MAX`
caveat say the field "includes the NUL". **Real git excludes it.** Verified: a file named
`run.sh` (6 characters) has flags `0x0006`; `a` has `0x0001`; `a.txt` has `0x0005`.
Therefore:

* `IndexEntryFlags::with(stage, path_len)` takes `path.len()` — **no +1** — and clamps to `0x0FFF`.
* `name_length()` returns the masked 12 bits as stored (already excluding the NUL).
* `to_bytes` writes `path.len().min(0x0FFF)`; `parse` treats the field as a *hint only* and always
  scans for the NUL (the doc comment requires this, and it is what makes the 4095-byte saturation
  case work). Do not branch on the stored length. A missing NUL before the end of `data` is
  `CorruptIndex`.

Do **not** edit the doc comments — they are frozen. Put the discrepancy in your final report.

## Behaviour details

* `parse` returns `consumed` = `(fixed + flags word(s) + path.len() + 1 + padding)`, padded from the
  **entry start**. `IndexEntryTooLong` when the path is past the format's limit (4095 bytes is the
  last representable length; longer is an error on write and on read when it cannot fit).
* `parse` errors: truncated fixed part or terminated path/NUL → `CorruptIndex { offset, reason }`
  (use the offset within `data`); stage bits above 3 → `InvalidStage`; mode not one of
  `100644/100755/120000/40000/160000` → `InvalidEntryMode`.
* `to_bytes` errors: path containing NUL → `CorruptIndex`; path longer than 4095 → `IndexEntryTooLong`.
  It writes `extended_flags` verbatim (including the intent-to-add bit it does not interpret) **iff**
  the `extended` bit is set, and writes no second word otherwise. The bit and the word are the
  caller's, but the two must agree on output.
* `is_empty_blob(format)` compares `oid` with the hash of an empty body. Use
  `crate::object::hash_object(format, ObjectKind::Blob, b"")` (it is public) — SHA-1 empty blob is
  `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`.
* `compare_entries`: `a.path.as_slice().cmp(b.path.as_slice())`, tie broken by
  `a.stage().as_bits().cmp(&b.stage().as_bits())`; **no file-position tiebreak**.
* `IndexExtension::is_optional` is `signature[0].is_ascii_lowercase()`. `signature_str` is
  `String::from_utf8_lossy(&signature)`. `is_tree`/`is_reuc`/`is_untracked_cache`/
  `is_split_index_link` compare the exact 4-byte signatures `TREE`, `REUC`, `UNTR`, `link`.
* `IndexExtension::new` just stores the pair (no validation).
