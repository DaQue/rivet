## The invariants the docs spell out — implement them, don't approximate

1. **Search order is loose first, then packs in turn.** Never ask the caller which.
2. **A read that misses must `refresh()` and retry exactly once** before reporting
   `ObjectNotFound` — the object may be in a pack a concurrent `git gc` produced. Retry
   once, not in a loop.
3. **Every read verifies the hash** (loose: against its filename; packed: against the id it
   was found under). A mismatch is `Error::HashMismatch`, never a returned object.
4. **A `.pack` without its `.idx` (or vice versa) is skipped, not fatal** — that half-written
   state is normal while another process is indexing. `open` and `refresh` scan
   `objects/pack/` and keep the complete pairs.
5. **Writing always goes loose** — `write`/`write_raw` delegate to `LooseObjectStore`.
   There is no path that appends to a pack, and `write` returns the id the object hashes to.
6. **The object format is a property of the handle**, passed at `open`/`open_objects_dir`
   and used for every id in every path; nothing re-derives it per call.
7. **`read_typed`** is `read` plus a kind check: a kind mismatch is the documented error
   (see the doc comment), and it must not re-read the object twice.
8. **`resolve_prefix`** accepts a short (abbreviated) id: it must collect candidate ids from
   all stores, error on ambiguity if more than one matches, and error with
   `ObjectNotFound` for zero matches. Read the doc comment for the exact error variants and
   the minimum/maximum abbreviation rules it states.
9. **`oids`** returns the union of the loose and packed ids, deduplicated, with a
   deterministic order (documented in the doc comment). It is an inventory, not a cache.
10. **Only delta bases are cached**, via the existing `DeltaBaseCache`; never cache whole
    objects.

Where a doc comment contradicts this brief, the **doc comment wins** — say so in your report.

## Tests (required)

Add `#[cfg(test)] mod tests` at the bottom of `odb/mod.rs`, using `tempfile::TempDir` and
private hand-built layouts (a `objects/xx/yyyy…` tree written with `flate2` or via
`LooseObjectStore`) — **your tests must not need a pack**, because `src/pack/` is still
scaffolded and would panic. Cover:

* `open` on a non-existent objects dir succeeds and finds nothing; `contains` is false and
  `read` is `ObjectNotFound`.
* `open` on a `git init`-shaped `.git` directory points at the right `objects` dir and
  reports the format it was given.
* `write` then `read` / `read_header` / `read_typed` round-trip, `contains` true, and the
  written id equals `git hash-object`'s for the same bytes (it comes from
  `crate::object::hash_object`, so assert a hard-coded known id for one case).
* `read_typed` with the wrong kind errors; with the right kind succeeds.
* `resolve_prefix` with a 7-hex prefix unique in the store resolves to the full id; a prefix
  matching nothing is `ObjectNotFound`. Only test ambiguity if you can produce two ids with a
  shared prefix without a pack — otherwise skip it and say so.
* a stray non-hex file and an empty `pack/` directory next to real objects are ignored by
  `open`, `oids` and `contains`.

Then extend the real-Git interop already used for loose objects — a **new** integration test
`crates/rivet-core/tests/odb_git_differential.rs` (mirror the shape of
`tag_git_differential.rs`): `git init` a temp repo, `git hash-object -w` a blob and a tree,
then read both through `Odb::open(...)` and assert bytes and ids match `git cat-file`.
Git is the oracle; no pack involvement.
