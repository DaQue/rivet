## The real `sha1-checked` 0.10 API (verified from the crate source — do not guess)
The crate root exports: `Sha1`, `Builder`, `CollisionResult`, and re-exports `Digest`
(`pub use digest::{self, Digest}`). There is **no** `Sha1Checked` and **no**
`Sha1CheckedBuilder` — that import is the source of the E0432 error.

```rust
use sha1_checked::{Builder, CollisionResult, Digest, Sha1};

Sha1::new()                       // -> Sha1  (impl Default too)
Sha1::builder()                   // -> Builder; .detect_collision(bool) .safe_hash(bool) .use_ubc(bool) .build() -> Sha1
Sha1::try_digest(data: impl AsRef<[u8]>) -> CollisionResult      // associated fn
hash_value.try_finalize()         // -> CollisionResult
CollisionResult::hash(&self) -> &Output<Sha1>   // 20-byte digest
CollisionResult::has_collision(&self) -> bool
```
`Sha1` also implements the standard `Digest` trait (`update`, `finalize`, etc.), so the
ordinary RustCrypto `Digest` flow works through `Sha1::new()`. Git's SHA-1 is *collision
detecting* SHA-1: prefer `try_digest`/`try_finalize` and surface a collision as an error
rather than silently returning a weak hash.
