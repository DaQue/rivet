## Behaviour rules the doc comments require

1. **Loose wins over packed** when both hold the id.
2. **A miss ends the function**: `ObjectNotFound`. `read` does **not** refresh — see the trap below.
3. **Never swallow errors with `if let Ok(...)`.** A loose read that fails with anything other than
   `ObjectNotFound` is the answer and must be returned unchanged: reporting a corrupt loose object
   as `ObjectNotFound` would be a lie. The doc comment's `# Errors` list is the contract.
4. **Every read verifies the hash** — loose content that does not hash to its filename, a packed
   object that does not match the id it was found under, a delta that does not reconstruct to what
   the `.idx` claims → `HashMismatch`. Not optional, not a debug-build-only check.
5. When a pack read needs a delta base it goes through `base_object` and the `RefCell`
   `DeltaBaseCache` — **bases only, never whole objects**.
6. The pack call is `pack.read(oid, Some(self))`: `Odb` is the `BaseProvider` that lets a
   `REF_DELTA` base live in another pack.

## The trap that killed the last attempt — read this before you write `read`

`refresh` is `pub fn refresh(&mut self)` and `packs` is a plain `Vec<PackedObjectStore>`. A previous
attempt put `let mut this = self; this.refresh();` inside `read` and died on
`error[E0596]: cannot borrow *this as mutable, as it is behind a & reference`. Do not re-abstract the
borrow, do not wrap the field in a `RefCell`, do not change any signature. `read(&self)` never
refreshes: freshness is the caller's job, and the `contains` doc comment says so outright — *"a
`false` is only as fresh as the last refresh"*.

## Tests

### In `odb/mod.rs` (bottom, `#[cfg(test)]`)

Fixtures built **without** the pack path: `LooseObjectStore` writes (its `write` is implemented) or
raw compressed files written by hand.

* `read` returns the object for an existing loose id, and `ObjectNotFound` for a plausible id that
  is absent.
* `read` on a **corrupt** loose file (right path, wrong bytes) → `HashMismatch`, not a panic.
* `read_typed` returns the object for the right kind and the documented error for a wrong one.
* `read_header` agrees with `read` on kind and size.

### `tests/odb_git_differential.rs` (new file, real git as the oracle)

Follow the style of the existing `tests/odb_loose_git_differential.rs` (read it **once**, first
120 lines are enough):

* `git init` a temp repo; `git hash-object -w --stdin` a blob and a small tree; `Odb::read` each id
  and assert the bytes equal `git cat-file -p`, and that the id round-trips.
* `git fsck --strict` afterwards: fail only on lines containing `error`/`missing`/`corrupt`/`bad`/
  `fatal`; `dangling` and `notice` are informational and must **not** fail the test.
* Skip gracefully (no panic) if `git` is not on PATH.

Known-good anchor (verified against real git): `b"hello from rivet\n"` →
`b4e2bc81abc981e1056a883f86cdfe9971ac7295`. When a test and real git disagree, **git is right** —
fix the test expectation, never the implementation to match a wrong test, and say so in your report.
