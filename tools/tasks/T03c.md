## Decisions already made — follow them, do not re-litigate

1. **`parse_loose_header` cannot name an object.** It receives no id, yet its documented
   error is `Error::CorruptObject { oid, reason }`. Construct it with
   `ObjectId::zero(ObjectFormat::Sha1)` as a placeholder, and have `read` / `read_header`
   re-attach the id they were given:

   ```rust
   .map_err(|e| match e {
       Error::CorruptObject { reason, .. } => Error::CorruptObject { oid: *oid, reason },
       other => other,
   })
   ```

   The placeholder must never escape the module: a corrupt file read through `read(oid)`
   reports `oid`, not a zero hash. Cover that with a test.

2. **Content verification on read.** After inflating, compare the recovered id against the
   requested one by recomputing it with `hash_object(self.format, kind, body)`. A
   mismatch is `Error::CorruptObject { oid: *oid, .. }` — never a silent success.

3. **`read_header` must not materialise the body.** Inflate until the NUL that ends the
   header, then keep inflating the remainder through a fixed-size buffer to *count* the
   bytes and discard them. The returned size is the body's real byte count; if it differs
   from the header's declared length, that is `CorruptObject`, not a returned lie.

4. **`write_raw` files an object; `write` is a thin adapter** that passes
   `object.kind()` / `object.data()` to it. Writing is: skip if `path_for(&id)` already
   exists (no rewrite, mtime unchanged), otherwise create the two-hex subdirectory, write
   the zlib-compressed buffer to a temp file whose name is **not** derived from the id,
   set the file read-only (mode `0o444`, Git's convention), then rename it into place. The
   rename is the atomicity; the read-only bit is why `remove` must clear it first.

5. **`oids` skips, never errors, on junk.** It is a recovery/indexing aid: ignore entries
   whose names are not valid hex of the right width, ignore temp files and any
   non-directory at the top level, and ignore subdirectories inside a two-hex directory.
   A missing `objects` directory yields an empty `Vec`, consistent with `open`'s "a store
   over a non-existent directory simply finds no objects"; any other I/O failure is
   `Error::IoAtPath` with the path that failed.

Where the doc comment and this brief appear to disagree, **the doc comment wins** — report
the conflict in your final message instead of guessing.

## Tests (required; they must fail if the logic is wrong)

Add `#[cfg(test)] mod tests` at the bottom of `loose.rs` using `tempfile::TempDir`.
At minimum cover:

* round-trip for all four kinds: `write` then `read` returns identical bytes and the same
  id; `contains` true, and `path_for` matches the `xx/yyyy…` layout for both formats.
* **the id is Git's id** — hard-code at least one known pair (e.g. `blob` with body
  `b"hello\n"` on a sha1 store must be
  `ce013625030ba8dba906f756967f9e9ca394464a`) and assert it, so a wrong header format
  fails the test.
* `read` on a truncated / corrupt file is `Err`, not a panic and not a wrong object.
* `read(oid)` for a corrupt object names **the requested id** in the error (decision 1).
* writing the same object twice leaves the file's mtime untouched (no rewrite).
* `remove` then `read` is `ObjectNotFound`; `oids` lists exactly the written ids and
  survives a stray junk file next to them.

Then add the real-Git differential test as a **new** integration test file
`crates/rivet-core/tests/odb_loose_git_differential.rs` (same shape as the existing
`tag_git_differential.rs`): in a temp dir, `git init`, create a blob with
`git hash-object -w`, read it with `LooseObjectStore` and assert the bytes and id match
Git's; then write an object with rivet and assert `git cat-file -p <id>` prints the same
bytes and `git fsck --strict` accepts the repository. Git is the oracle — if the two
disagree, rivet is wrong.
