## Behaviour rules the doc comments require

1. A read that misses must **refresh once and retry** (the object may have landed in a pack
   this handle has not scanned) and only then return `ObjectNotFound`.
2. **Loose wins over packed** when both hold the id.
3. **Every read verifies the hash** — loose content that does not hash to its filename, a
   packed object that does not match the id it was found under, a delta that does not
   reconstruct to what the `.idx` claims → `HashMismatch`. Not optional, not a debug build.
4. `write`/`write_raw` go to the loose store and return the id; they never touch a pack.
5. When a pack read needs a delta base, it goes through `base_object` and the `RefCell`
   `DeltaBaseCache` — **bases only, never whole objects**.
6. `resolve_prefix` over the union of loose and packed ids, deterministic tie-breaks.

## Tests

### In `odb/mod.rs` (bottom)

`#[cfg(test)]` tests built on fixtures you can create without the pack path: `LooseObjectStore`
writes (its `write` is implemented) or raw compressed files written by hand.

* `read` returns the object for an existing loose id and `ObjectNotFound` for a plausible id
  that is absent.
* `read` on a **corrupt** loose file (right path, wrong bytes) → `HashMismatch`, not a panic.
* `read_typed` returns the object for the right kind and the documented error for a wrong one.
* `read_header` agrees with `read` on kind and size.
* `write` then `read` round-trips; the id is the git-computed one.
* `resolve_prefix` with a unique prefix, an ambiguous prefix and a missing prefix → three
  distinct outcomes.

### `tests/odb_git_differential.rs` (new file, real git as the oracle)

Following the pattern of the existing `tests/odb_loose_git_differential.rs` and
`tests/tag_git_differential.rs` (Read them once for style — they are short):

* `git init` a temp repo; `git hash-object -w --stdin` a blob and a small tree; then
  `Odb::read` each id and assert the bytes equal `git cat-file -p`'s output and that the id
  round-trips.
* rivet-written object → **real git reads it**: `Odb::write_raw` a blob, then assert
  `git cat-file -t` / `-p` and `git hash-object -t blob --stdin` reproduce rivet's id.
* `git fsck --strict` on the repo afterwards: fail only on lines containing
  `error`/`missing`/`corrupt`/`bad`/`fatal`; `dangling` and `notice` are informational and
  must **not** fail the test.
* Skip gracefully (no panic) if `git` is not on PATH.

Known-good anchors (verified against real git): `b"hello from rivet\n"` →
`b4e2bc81abc981e1056a883f86cdfe9971ac7295`. When a test and real git disagree, **git is right**
— fix the test expectation, never the implementation to match a wrong test, and say so in
your report.
