## Behaviour rules the doc comments require

1. `write`/`write_raw` go to the **loose** store and return the id; they never touch a pack.
2. `write` returns the id git itself would compute for the same object — the id is recomputed from
   the canonical header + body, never taken from a caller field.
3. `resolve_prefix` searches the **union** of loose and packed ids, with deterministic tie-breaks;
   an ambiguous prefix and a missing prefix are **different** error variants per the doc comment.
4. Writes must be crash-safe in the way the loose store already is (temp file, then rename) — call
   into `LooseObjectStore`, do not hand-roll the file write.

## Tests

### In `odb/mod.rs` (bottom, `#[cfg(test)]`, add to what is already there)

* `write` then `read` round-trips; the id is the git-computed one (anchor:
  `b"hello from rivet\n"` → `b4e2bc81abc981e1056a883f86cdfe9971ac7295`).
* `write_raw` produces the same id as `write` for the same kind and body.
* `resolve_prefix` with a unique prefix, an ambiguous prefix and a missing prefix → three distinct
  outcomes (assert the error variants, not just `is_err()`).

### `tests/odb_git_differential.rs` (extend the existing file)

* rivet-written object → **real git reads it**: `Odb::write_raw` a blob, then assert
  `git cat-file -t` / `-p` and `git hash-object -t blob --stdin` reproduce rivet's id.
* `git fsck --strict` on the repo afterwards: fail only on lines containing
  `error`/`missing`/`corrupt`/`bad`/`fatal`; `dangling` and `notice` are informational and must
  **not** fail the test.
* Skip gracefully (no panic) if `git` is not on PATH.

When a test and real git disagree, **git is right** — fix the test expectation, never the
implementation to match a wrong test, and say so in your report.
