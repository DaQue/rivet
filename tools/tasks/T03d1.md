## Behaviour the doc comments require (implement them, don't approximate)

1. `open` is `open_objects_dir(git_dir.join("objects"), format)` plus the pack scan; a
   missing `objects/pack/` is **not** an error.
2. The pack scan keeps only **complete `.pack`/`.idx` pairs**; a lone `.pack` or lone `.idx`
   is skipped, not fatal. A corrupt `.idx` **is** fatal (`CorruptPackIndex` /
   `UnsupportedPackIndexVersion`); a `.pack` is only checksum-checked when read.
3. `refresh` re-runs that scan; existing packs stay, newly complete pairs are added. It must
   not drop packs it can no longer see unless the doc comment says so.
4. `contains` asks the loose store, then each pack — no `refresh`, no I/O error (it returns
   `bool`).
5. `oids` is the **union** of loose and packed ids, **deduplicated**, in the deterministic
   order the doc comment specifies. It is an inventory, not a cache.
6. `format`/`objects_dir`/`loose`/`packs` are accessors with the exact return types in the
   scaffold.
7. `add_pack(pack, index)` indexes the pair the way `open` does (`index` is `Option`, so the
   no-index case has an error path documented in the doc comment).
8. `base_object` is the private helper the pack reader uses for delta bases; read its doc
   comment for the cache rule — **only delta bases are cached, never whole objects**.
9. Every id in every path uses `self.format`; nothing re-derives it per call.

Where a doc comment contradicts this brief, the **doc comment wins** — say so in your report.
