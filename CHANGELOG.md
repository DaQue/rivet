# Changelog

* 2026-11-11 — `apply --whitespace=fix` finds a hunk whose context differs from the file only by whitespace errors (both sides repaired alike, the post-image keeps the repaired file lines), reports the context lines it checks, and `--whitespace=error` dies on its whitespace errors before a hunk that does not fit is reported (`s_apply_whitespace_fix_context`).
* 2026-11-10 — `ls-remote --sort=*refname` / `-*refname` / `v:*refname` / `*refname:short` sort as git does, with its `malformed field name: *` and `unrecognized %(*refname) argument` fatals (`s_ls_remote_sort_deref`).
* 2026-11-10 — `apply --ignore-whitespace` / `--ignore-space-change` (and the `--no-` forms, `apply.ignorewhitespace=change|none`): context lines match as git's `fuzzy_matchlines` does, the post-image keeps the file's own spelling of them, a value is `error: option `ignore-whitespace' takes no value` (exit 129) (`s_apply_ignore_whitespace`).
* 2026-11-10 — `apply --no-add` ignores the additions of the patch, forward, `-R`, `--cached` and for a new file (`s_apply_no_add`).
* 2026-11-10 — `apply --whitespace=<nowarn|warn|error|error-all|fix|strip>` and `apply.whitespace`: added lines are checked against `core.whitespace` / the `whitespace` attribute (`blank-at-eol`, `space-before-tab`, `indent-with-non-tab`, `tab-in-indent`, `cr-at-eol`, `blank-at-eof`, `tabwidth=`), reported as `<patch>:<line>: <reason>.` with git's squelching, summary and exit status, and repaired under `fix` (`s_apply_whitespace`).
* 2026-11-10 — `diff -M[<n>]` / `--find-renames[=<n>]` / `--no-renames`: the last one wins, `-M` forces detection over `diff.renames=false`, the score is git's `parse_rename_score` (`-M.5`, `-M50%`, `-M5.`), and a bad score is `error: invalid argument to find-renames` (exit 129) instead of clap's unknown-argument error (`s_diff_find_renames`).
* 2026-11-10 — `mv` keeps an intent-to-add (or skip-worktree) entry's flags, and `stash push`/`create` over an intent-to-add path fail as git does (`error: Entry '<path>' not uptodate. Cannot merge.`, `Cannot save the current worktree state`; exit 1, or 128 with a pathspec/`create`) (`s_ita_mv_stash`).
* 2026-11-10 — `bisect visualize`/`view <word> ...` treats the word as git does: nothing bisected is silent exit 1 first, `log` is the `log` form, and a word that names no command is `git: '<word>' is not a git command. See 'git --help'.` (exit 255) instead of a refusal (`s_bisect_visualize`).
* 2026-11-10 — `commit-tree` honours a non-UTF-8 `i18n.commitEncoding`: the commit gets git's `encoding <value>` header and the message bytes are left alone instead of the refusal (`s_commit_tree_encoding`).
* 2026-11-10 — `grep --exclude-standard` / `--no-exclude-standard`: `--untracked --no-exclude-standard` also searches ignored files, `--no-index --exclude-standard` skips them (`.gitignore` files and `info/exclude`), the last flag wins, and a tracked search is `fatal: --[no-]exclude-standard cannot be used for tracked contents` (`s_grep_exclude_standard`).
* 2026-11-10 — `grep --no-index` searches the current directory in or out of a repository (`.git` skipped, no ignore file consulted, `--cached`/`--untracked` clash, revisions are paths that must exist) as git does (`s_grep_no_index`).
* 2026-11-10 — GAPS no longer lists `apply --reject` together with `--3way` as missing: it already prints git's `options '--reject' and '--3way' cannot be used together` (`s_apply_three_way`).
* 2026-11-10 — `blame -M`/`-C` (any number, with `-w`/`-L`) work over a file with uncommitted changes instead of failing: lines the work tree moved or copied are traced to their commits, the rest are `Not Committed Yet` (`s_blame_worktree_move`).
* 2026-11-09 — `format-patch --attach[=<boundary>]`, `--inline[=<boundary>]`, `--no-attach` and `format.attach` send each patch as a `multipart/mixed` message (text part, then the patch as `text/x-patch` with its file name), the last option wins, the default boundary is the version string, an attached patch carries no signature (`s_format_patch_attach`).
* 2026-11-09 — `format-patch <range> -- <path>...` keeps the commits that touch the paths and only those paths in each patch (no diffstat in a cover letter, as git); `log <range> -- <path>` no longer lists a commit whose only parent is the range boundary when it leaves the paths alone (`s_format_patch_paths`).
* 2026-11-09 — `grep` takes `--and`, `--or`, `--not`, `(`, `)` and `--all-match`: a boolean expression over `-e` patterns compiled with git's grammar (`--and` binds tighter, adjacent patterns are an implicit or) and git's fatals for a malformed one, and the words are options only before the first non-option word (`s_grep_boolean`).
* 2026-11-09 — `format-patch -k` keeps a multi-line subject (sent as an RFC 2047 word with `=0A`), a subject with an `=?` is encoded, and runs of blanks or a leading blank in a subject are kept as written instead of refused or collapsed (`s_format_patch_keep_subject`).
* 2026-11-09 — `symbolic-ref` accepts a one-level lowercase target (`symbolic-ref FOO foo`), reads it back (`--short`, `--no-recurse`, `-q`) and deletes it, instead of refusing by name (`s_symbolic_ref_one_level`).
* 2026-11-09 — `rerere gc` reads `gc.rerereResolved`/`gc.rerereUnresolved` as git does: a number is days, `all` prunes everything, any other value is a cut-off date (`2.months.ago`, `yesterday`); `parse_expiry_ago` knows `yesterday` (`s_rerere_gc_dates`).
* 2026-11-09 — `log --graph` with `--left-right`, `--cherry-mark` or `--cherry` draws the mark (`<`, `>`, `=`) in place of the `*`, and a range (`A..B`, `A...B`, `^A`) or side filter drops the parents outside the walk from the graph as git does (`s_log_graph_marks`).
* 2026-11-06 — `log --left-right` puts `<`/`>` in front of the id (`commit <` lines, `--oneline`) and `%m` expands to the mark of a symmetric difference (`s_log_left_right`).
* 2026-11-06 — `apply` reports a damaged `GIT binary patch` block as git does (`error: invalid base85 alphabet <c>` / `inflate: data stream error (...)`, then `error: corrupt binary patch at <file>:<line>: <text>`; `<stdin>` for standard input), applies the patches before it and exits 0, or says `No valid patches in input` (128) when its input had none (`s_apply_binary_corrupt`).
* 2026-11-06 — `gc` keeps every pack at least `gc.bigPackThreshold` bytes (`k`/`m`/`g` suffixes) like a `.keep` pack, and a bad value is git's `bad numeric config value ... invalid unit` fatal (`s_gc_big_pack_threshold`).
* 2026-11-06 — `gc --auto` runs the `pre-auto-gc` hook before it says anything (a failing hook cancels silently), prints its notice on stderr as git does, treats `gc.auto=0` as off for the pack limit too, and leaves loose refs unpacked (`s_gc_pre_auto_gc`).
* 2026-11-06 — `log` (and `bisect visualize`/`view`, which run it) reports an unknown option as `fatal: unrecognized argument: <word as typed>`, exit 128, instead of a clap usage error (`s_log_unrecognized`).
* 2026-11-06 — `ls-remote --sort=refname:short` (also `-`/`v:` forms) shortens each name against the local repository's refs as git does; `refname:dir`/`:base` are git's `unrecognized %(refname) argument` fatal, not a rivet refusal (`s_ls_remote_sort_short`).
* 2026-11-06 — `s_split_index_expire` no longer depends on the wall clock: the `1.second.ago` step waits past the cutoff and git's own `update-index --split-index` count is not recorded (the gate's G3 run of the difftest failed on the second boundary).
* 2026-11-06 — `config` (default scope: `--get`, `--get-all`, `--get-regexp`, `--list`) reads `config.worktree` after `config` once `extensions.worktreeConfig` is on; `--local` stays the shared file (`s_config_worktree_read`)
* 2026-11-06 — `checkout -b <new>` and `checkout -B`/`-f -B` over a cherry-pick or revert in progress drop `CHERRY_PICK_HEAD`/`REVERT_HEAD` and print `warning: cancelling a cherry picking in progress` (or `a revert`) after the switch message, as git does (`s_checkout_pick_state`).
* 2026-11-05 — `stash push`/`save`/bare `stash` read `-U<n>`, `--unified=<n>` and `--inter-hunk-context=<n>` as git reads an integer option (`k`/`m`/`g`, range, `requires a value`, `expects a numerical value`; `-1` is unset) and, without `--patch`, fail with `fatal: the option '--unified' requires '--patch'` (`s_stash_diff_context`).
* 2026-11-05 — `update-ref --stdin` reads a C-quoted field in line mode (refname, ids, symref words) and fails as git does: `badly quoted argument: <rest>`, `unexpected character after quoted argument: <rest>` (`s_update_ref_quoted`).
* 2026-11-05 — `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` are read as git's `parse_date_basic` reads them (`commit`, `commit-tree`, every identity): RFC 2822 (`Thu, 07 Apr 2005 22:13:13 +0200`), `mm/dd/yyyy`, `dd.mm.yyyy`, month/zone names, `AM`/`PM`, `hh:mm:ss.fraction`, `+hh:mm`; `now`, a date with no time of day and a result outside 1970..2099 are `fatal: invalid date format` (`s_commit_date_formats`).
* 2026-11-05 — `update-ref --stdin -0`/`--batch-updates` rejects a create that collides with a ref above or below its name as `rejected <ref> <new> <old> refname conflict` (with git's `cannot lock ref ... exists; cannot create` error), and without a batch the same text is the fatal (`s_update_ref_conflict`).
* 2026-11-05 — `repack --cruft --cruft-expiration=<date> --expire-to=<prefix>` (and `--no-expire-to`, last one wins) writes the objects the expiry drops to a cruft pack `<prefix>-<checksum>.{pack,idx,rev,mtimes}` with their own ages, as git does; ignored without `--cruft` (`s_repack_expire_to`).
* 2026-11-05 — `worktree repair --[no-]relative-paths` (and `worktree.useRelativePaths`) rewrite the `.git`/`gitdir` links of every work tree in the chosen style, report `absolute/relative path mismatch` as git does and set `extensions.relativeWorktrees` (`s_worktree_repair_relative`).
* 2026-11-04 — `repack --max-pack-size` is read as git reads a magnitude (base 0, `k`/`m`/`g`, unsigned 64 bit): every occurrence is checked in order (`expects a non-negative integer value…`, `expects a numerical value`, `requires a value`, `not in range [0,-1]`) and a limit under 1 MiB warns (`s_repack_max_pack_size`).
* 2026-11-04 — `repack --window`/`--depth` (and `--no-…`) are read as git reads them: the last one standing is validated (`expects an integer value…`, range, `requires a value`, `expects a numerical value`), a depth over 4095 warns `delta chain depth N is too deep, forcing 4095`, and nothing else changes (`s_repack_window_depth`).
* 2026-11-04 — `config --get-regexp`: every word after the pattern is a plain word as in git (`-z`, `--local`, `-t int` there are the value pattern or `wrong number of arguments`), and a `--` before the pattern is eaten (`s_config_get_regexp_words`).
* 2026-11-04 — `blame --until`/`--before`/`--max-count`/`--skip`/`--max-age`/`--min-age` are read as git reads them: validated (`fatal: '<v>': not an integer` / `not a number of seconds since epoch`, exit 128) and otherwise without effect (`s_blame_revlist_limits`).
* 2026-11-04 — `pull --rebase <remote> <branch>` replays only what follows the fork point of HEAD from that remote branch's tracking-ref reflog, as git does, instead of everything after the merge base (`s_pull_rebase_refspec`).
* 2026-11-04 — `format-patch --description-file=<file>` fills the cover letter body (leading blank lines dropped, line ends trimmed, an empty file keeps the placeholder) and dies with `unable to read branch description file` as git does (`s_format_patch_description_file`).
* 2026-11-04 — `format-patch -v <n>` / `-v<n>` / `--reroll-count=<n>` / `--no-reroll-count`: `[PATCH v<n>]` subjects, `v<n>-` file names (cover letter included), the last count wins (`s_format_patch_reroll`).
* 2026-11-04 — `worktree add --[no-]relative-paths` and `worktree.useRelativePaths` write relative `.git`/`gitdir` links and set `extensions.relativeWorktrees` (format version 1); relative links are read by `worktree list`/`prune`/`repair` and when opening a linked work tree (`s_worktree_add_relative`).
* 2026-11-04 — `bisect run` re-runs a command that exited 126 or 127 on a good revision and stops with `error: bogus exit code <n> for 'good' revision` (exit 1, back on the tested commit) when it fails the same way, as git does (`s_bisect_run_bogus`).
* 2026-11-04 — `update-ref --stdin` takes only `commit`/`abort` after `prepare` (`fatal: prepared transactions can only be closed`) and lets a closed transaction `start` again, as git does (`s_update_ref_prepared`).
* 2026-11-04 — `worktree add` answers a switch given a value (`--track=direct`, `--guess-remote=x`, ...) with git's `error: option `x' takes no value` and no usage, names a bad short switch `unknown switch`, and parses bundles such as `-fq` and `-bname` (`s_worktree_add_switches`).
* 2026-11-03 — `worktree add --orphan` makes an unborn branch work tree with git's option clashes and fatals; `--reason` without `--lock` is git's wording (`s_worktree_add_orphan`).
* 2026-11-03 — `rev-list --cherry` is `--right-only --cherry-mark --no-merges` (`s_rev_list_cherry_synonym`).
* 2026-11-06 — `log --cherry-pick`, `--left-only` and `--right-only` filter a symmetric difference as `rev-list` does, before `--skip`/`-n` (`s_log_cherry_pick`).
* 2026-11-03 — `diff-tree --stdin` reads its lines with no path limit once a tree-ish was given on the command line, as git does; a limit with no tree-ish still applies (`s_diff_tree_stdin_limit`).
* 2026-11-03 — `config --get-regexp` takes its pattern after `-t <type>`, `-t<type>`, `-f <file>`, `--file <file>` and `--file=<file>` (`s_config_get_regexp_after_opts`).
* 2026-11-03 — `blame --contents <file>` (`-` is standard input) blames that file as the final version of the path, its changed lines credited to `External file (--contents)` with git's `Version of <path> from <file>` summary (`s_blame_contents`).
* 2026-11-03 — `config --type=color` reads `no<attr>`/`no-<attr>` words (`nobold`, `no-ul`, ...): the positive attributes come first, then the sorted 22/23/24/25/27/29 codes (`s_config_color_no`).
* 2026-11-03 — `show --oneline`: one line with the abbreviated id, the last of `--oneline`/`--pretty`/`--format` wins and a later block layout abbreviates its `commit` line (`s_show_oneline`).
* 2026-11-03 — `clone -b <tag>` detaches `HEAD` at the tag's commit with git's detached-HEAD note, no branch or tracking config, bare or not (`s_clone_branch_tag`).
* 2026-11-03 — `clone` of an empty repository writes `branch.<default>.remote`/`merge` (not for `--bare`), as git does (`s_clone_empty_tracking`).
* 2026-11-01 — `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` in ISO form with a spaced offset are honoured and a bad value is git's `invalid date format` fatal, so commit ids match git's (G2 workflow parity green).
* 2026-11-01 — rebase interop proved against git: a plain (non-`-i`) rebase stopped on a conflict is continued, skipped or aborted by the other implementation in both directions with identical ids, reflogs and files (`s_rebase_interop_plain`); the GAPS bullet is closed.
* 2026-11-03 — `config -f`/`--file <path>` reads and writes one named file (a missing file is silent for `--get`, a fatal for `--list`), and two scopes together are git's `error: only one config file at a time`, exit 129 (`s_config_file`).
* 2026-11-03 — `config --get-color <slot> [<default>]` prints the escape sequence of the slot's colour or of the default word, nothing without either, git's errors for a bad value, a bad default and `--type` (`s_config_get_color`; a bare `key` is not compared, git crashes on it).
* 2026-11-03 — `config --type=int` on a write stores the number (`3k` becomes `3072`) and refuses text with git's `bad numeric config value '<v>' for '<key>': invalid unit` (`s_config_int_write`).
* 2026-11-04 — `bisect run` with a command that exits 128 or more stops with git's status `256 - code` (255 is 1, 130 is 126), not a fixed 126 (`s_bisect_flags`).
* 2026-11-04 — `update-index --again`/`-g` updates every merged entry that differs from `HEAD` (optionally limited by pathspecs) with the options given before it (`s_update_index_again`).
* 2026-11-05 — `repack --max-cruft-size` is read as git's magnitude, the cruft pack takes it (or `--max-pack-size` when it is 0) and a limit under 1 MiB warns once per pack (`s_repack_max_cruft_size`).
* 2026-11-05 — GAPS no longer lists `repack --keep-largest-pack`: git 2.56 has no such option (`unknown option`), so there is nothing to match.
* 2026-11-05 — `log --graph --format=format:<fmt>` draws no extra graph rows: the padding before the separator newline is skipped when the entry has no newline of its own, as git's `missing_newline` (`s_log_graph_format_separator`).
* 2026-11-05 — `mktree` reads a mode as git's `strtoul` into an `unsigned int` does (sign negates modulo 2^64, low 32 bits kept) instead of refusing signed or wide modes (`s_mktree_wrap`, tree ids compared).
* 2026-11-06 — `log --cherry-mark` and `--cherry` mark the commits of a symmetric difference `=`/`+` (and `%m`) as git does (`s_log_cherry_mark`).
* 2026-11-09 — `log --boundary` lists the excluded parents after the commits marked `-` (`o` with `--graph`, `%m` is `-`), ordered as `rev-list --boundary` does (`s_log_boundary`).

* 2026-11-11 — `apply --inaccurate-eof` treats a hunk whose last line lost its `\ No newline at end of file` marker as ending without a newline on both sides, as git does (`s_apply_inaccurate_eof`).
